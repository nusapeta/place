# Nusapeta Place 0.2.1

Released 2026-11-20. A patch release: 0.2.0 shipped two endpoints under the
bundle prefix instead of the paths the API documents.

## Fixed

- `GET /suggest` and `GET /admin/reverse` are registered at the documented
  paths. 0.2.0 mounted them as `/place/suggest` and `/place/admin/reverse`; the
  gateway strips `/place` before forwarding, so both answered
  `404 route not found` in the bundled deployment.

## Changed

- The server prints the address it actually bound, so `--bind 127.0.0.1:0` can
  be used by a caller that needs the kernel-assigned port. The end-to-end tests
  use it to stop racing each other for a free port.

## Versions

| Component | Value |
|---|---|
| Server | 0.2.1 |
| Index format | 2 (readers still accept 1) |
| API | v1 |

No index rebuild. The 0.2.0 index and manifest are unchanged and remain the
current data release (`data-2026.11.1`).

## Install

```bash
docker run --rm -p 127.0.0.1:8090:8090 -v "$PWD:/data:ro" \
  ghcr.io/nusapeta/place:0.2.1 \
  --index /data/places-v2-2026.11.idx \
  --manifest /data/places-v2-2026.11.idx.json \
  --verify-checksum
```

## Upgrading from 0.2.0

Drop-in for the server binary and image. Anything that called
`/place/suggest` or `/place/admin/reverse` against the geocoder directly (not
through the gateway) must use `/suggest` and `/admin/reverse`.
